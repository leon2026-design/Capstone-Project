# MA-06 Contact Enrichment

MA-06 adds a bounded research and review pipeline alongside the existing MA-05
identity and social-profile workflow. It does not change `Master_Contacts`,
campaign engagement, report parsing, automatic merges, or outreach behavior.

## Current provider support

The repository does **not** include a live search provider or platform API
credentials. `djEnrichmentCreateFixtureProvider()` is deterministic synthetic
test data only; it must not be described as live discovery. With no provider,
MA-06 creates `NEEDS_RESEARCH` jobs and useful search queries without inventing
URLs or search results. A researcher may add a URL with
`djEnrichmentAddManualCandidate()`.

Live provider capability must be explicitly configured by the caller. A
provider has this shape:

```js
{
  providerId: "AUTHORIZED_SEARCH",
  authorized: true,
  authorizedHosts: ["search.example.org"],
  supportedPlatforms: ["INSTAGRAM", "FACEBOOK"],
  capabilities: {
    searchPublicProfiles: true,
    retrievePublicProfiles: false,
    normalizeUserSuppliedUrls: false
  },
  search: function(query, context) {
    // Use context.fetch(apiName, httpsUrl, options) for outbound requests.
    // Return { candidates: [...] } with source URLs and evidence.
  }
}
```

Only providers marked `authorized: true` are called. Outbound requests must use
`context.fetch()`, which checks HTTPS and the exact `authorizedHosts` allowlist,
disables automatic redirects, and records each request in
`DJ_Enrichment_API_Usage` and the existing `trackedFetch()` API inventory.
Provider search invocations are also counted in each job's `Attempt Count`.
Providers are responsible for honoring any source-specific terms and request
limits. A provider should mark only transient failures with
`error.retryable = true`; invalid credentials and permanent errors are not
retried. Do not fetch restricted profiles or use anti-automation bypasses.

## Workflow

For script-editor use, start with the actual contacts and unresolved observations:

```js
const ss = SpreadsheetApp.getActive();
const result = djEnrichmentRunSelected(
  ss,
  [], // no configured live provider: creates offline research jobs
  { platforms: ["INSTAGRAM", "FACEBOOK", "SOUNDCLOUD", "MIXCLOUD"] }
);
console.log(JSON.stringify(result));
```

For a configured provider, pass it in place of `[]`. To process existing queued
jobs after an interrupted run, call `djEnrichmentResume(ss, providers, options)`.
Processing is bounded by `maxCandidatesPerRun`, `maxProviderRequests`,
`maxApiCallsPerRun`, and `maxAttempts`; `requestDelayMs` can add a bounded delay
between provider calls. No enrichment is scheduled from `Main.js`.

Manual research and review:

1. Use the job's `query` to research through an authorized source.
2. Submit only the real candidate URL/value, evidence, and source URL with
   `djEnrichmentAddManualCandidate(ss, jobId, candidate, researcher, notes)`.
3. Review a supported candidate with
   `djEnrichmentReview(ss, enrichmentId, "APPROVE" | "REJECT" | "NEEDS_RESEARCH", reviewer, notes)`.
4. Transfer an approved social candidate with
   `djEnrichmentTransferApproved(ss, enrichmentId, observationId)`. This requires
   a real MA-05 `APPROVED_LINK` identity review and saves only a `PENDING_REVIEW`
   profile through `djSocialProfileSave()`.
5. A reviewer must separately use `djSocialProfileReview()` to verify or reject
   the MA-05 profile. Enrichment approval never verifies it automatically.

An enrichment candidate for an existing contact cannot be transferred unless
the supplied observation is a real observation already approved for that same
contact. This avoids inventing an observation ID or representing an enrichment
source as a promotional report.

## Storage

The feature creates these sheets only when needed and rejects unexpected
headers:

- `DJ_Enrichment_Jobs` — target, platform, source, query, state, attempts,
  timestamps, and recoverable error details.
- `DJ_Enrichment_Candidates` — separate candidate URLs/values, source,
  confidence ranking, review state, and bounded candidate metadata.
- `DJ_Enrichment_Evidence` — individual evidence values, source URLs,
  timestamps, and deterministic evidence classifications.
- `DJ_Enrichment_Review_History` — manual candidate submissions and
  non-overwritable reviewer decisions.
- `DJ_Enrichment_API_Usage` — each outbound request made through the authorized
  provider context.

Candidate confidence is only a deterministic ranking aid, not an identity
probability. Name-only matches and unsupported profile claims are not verified.
Conflicting candidates cannot be approved. Rejected decisions remain in history.
Spreadsheet-formula-like values are escaped before storage.

Candidate identity is read from the identified `Master_Contacts` row or the
original MA-04/MA-05 observation, not from caller-supplied replacements.
Contacts marked by recognized do-not-contact, do-not-research, or privacy opt-out
columns are excluded. Existing verified profiles, pending candidates, and prior
jobs are reused rather than duplicated. `NOT_FOUND` means only that the
configured source returned no candidate for that query.

## Validation and local demo

Run the focused checks from the repository root:

```powershell
node local-tests\DJEnrichment.test.cjs
node local-tests\DJEnrichmentDemo.cjs
```

The demo uses fictional identities, reserved `.test` URLs, and fixture
providers. It demonstrates two candidate reviews, MA-05 transfer and verification,
idempotent rerun, and offline task creation. It performs no live search.

Live contact discovery remains unimplemented until an authorized provider is
configured and its use is demonstrated. Apps Script's own execution and
`UrlFetchApp` limits apply; this implementation cannot impose a network timeout
inside an external provider beyond the platform's request/runtime limits.
